# Writeup

**Matching approach.** I treated matching as evidence scoring, not name matching, because the data punishes names: there are rebrands (Riverbend Manor Care Center is now Bellhaven of Chagrin Falls) and lookalikes (an "Amberly Manor" in Colorado, "Union Square Senior Living" at a different address). Every website location is scored against every CRM account on independent signals: normalized street address (50 points), the website's administrator being a contact on the account (25), phone (20), name similarity with the brand word removed (15), plus small signals for city, care type and @bellhavenliving.com contacts. 45+ is a match and a different state disqualifies. Several accounts matching one location are duplicates; a deterministic rule keeps the copy already under Bellhaven, then billing history, contacts, score. Proposals are "desired state minus current state", so applied fixes never come back, and rejected ones are fingerprinted so the daily run never asks again. The billing SOP picks between re-parenting and a change of ownership (Tiffin, Marietta), and it is re-checked on fresh data at approval time. Accounts under Bellhaven that no page lists go to Needs Review with a note rather than Inactive, because the website can't say whether they were sold or closed, and Sandusky has revenue and AR. The scraper also reads the home page, which is the only place the 35th community (Findlay) is linked.

**How I used AI.** I used Claude (Claude Code) for most of the work. First it explored the website and the API with me to catalog the traps before any code: the hidden 35th community, the zip typo, the PO box billing address, the duplicates left over from the Harborview and Cedar Trail acquisitions. Then it wrote the modules and 20 tests. I checked the output against the data myself: the tests, a second run that proposed nothing new, and the evidence page of each proposal before it was approved.

**What I'd build next.** Move contacts from duplicate copies to the survivor; a lower-priority queue for phone and administrator changes; a shared Postgres store so the scheduled run and the review app share decisions; a Slack digest of new proposals; flag parent accounts whose facilities have all moved (Harborview).
